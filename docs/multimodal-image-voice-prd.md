# OpsGuard 多模态输入 PRD：图片识别与语音输入

## 1. 文档信息

- 文档状态：Phase 3 已实现
- 创建日期：2026-05-21
- 面向版本：OpsGuard 多模态能力第一阶段
- 目标用户：中文运维用户、SRE、平台工程师、值班人员
- 多模态服务建议：阿里云百炼 Model Studio / 阿里云智能语音交互
- 本期明确不做：移动端专项适配、屏幕录制分析、自动抓取用户桌面截图、语音播报

## 2. 背景

OpsGuard 当前已经具备文本对话、真实 MCP 工具执行、安全审批、推理链路、Runbook、知识库和运维报告能力。但真实运维场景中，用户不一定总是通过结构化文字输入问题。

常见情况包括：

- 用户手里只有一张终端报错截图。
- 用户从 Grafana、Zabbix、Prometheus、云监控或工单系统截了一张图。
- 用户现场巡检时不方便打字，希望直接语音说明问题。
- 用户知道现象但不知道如何准确描述服务名、路径、端口或日志关键字。
- 夜间值班时，输入长命令、长路径、长错误堆栈的成本很高。

因此，OpsGuard 需要补齐两类高价值输入方式：

1. 图片识别：理解运维截图、日志截图、配置截图、告警截图。
2. 语音输入：把自然语言语音转为可信、可追溯、可确认的运维请求。

核心目标不是炫技式“能看图、能听语音”，而是让多模态输入进入 OpsGuard 已有的安全、证据、审批和真实执行闭环。

## 3. 产品目标

### 3.1 业务目标

- 降低运维人员输入成本，减少手工抄写错误。
- 让截图、语音、文本都能进入同一套智能体诊断流程。
- 提升故障信息采集效率，尤其是终端报错、告警截图、配置截图和现场语音描述。
- 强化“证据链路可追溯”，让用户知道智能体基于图片/语音识别到了什么。

### 3.2 用户体验目标

- 用户上传截图后，OpsGuard 能自动提取关键信息并生成诊断计划。
- 用户录音后，OpsGuard 能识别中文运维表达，并进行运维术语纠错。
- 如果语音或图片中涉及写操作，系统必须先复述并走现有审批机制。
- 推理链路必须显示“来自图片识别”“来自语音识别”“来自模型推断”“来自真实工具执行”等证据来源。

### 3.3 技术目标

- 基于阿里云能力完成第一阶段接入。
- 多模态识别结果必须结构化保存，供推理链路、知识库和审计日志复用。
- 多模态能力以服务层封装，不直接耦合前端组件和具体云厂商 SDK。
- 保持现有 Agent 执行真实性原则：图片/语音识别结果只能作为输入证据，不能替代真实 MCP 工具执行。

## 4. 用户画像与场景

### 4.1 一线运维人员

场景：

- 在服务器终端看到报错后截图上传。
- 用语音描述：“帮我看一下 nginx 为什么启动失败。”
- 希望系统自动识别服务名、错误行、端口和路径。

痛点：

- 不想手动复制长日志。
- 不确定截图里的错误关键字是什么。
- 语音说服务名、路径、端口比打字更快。

### 4.2 值班 SRE

场景：

- 收到告警后上传监控平台截图。
- 通过语音描述故障影响范围。
- 希望系统自动关联检查服务状态、日志、端口、最近变更。

痛点：

- 夜间处理告警时输入效率低。
- 图片和语音信息容易遗漏。
- 需要快速进入真实诊断链路。

### 4.3 项目评委/新用户

场景：

- 上传一张 systemctl status 或 Grafana 告警截图，观察系统是否能理解。
- 使用语音输入简单运维问题，观察是否能转成合理请求。

痛点：

- 评委不熟悉项目规则，不希望被要求输入固定格式。
- 需要直观看到智能体不是假输出，而是基于证据和真实工具执行。

## 5. 功能范围

### 5.1 图片识别输入

#### 5.1.1 支持的图片类型

第一阶段支持：

- 终端截图：`systemctl status`、`journalctl`、`ps`、`df`、`ss/netstat` 等输出。
- 日志截图：错误日志、堆栈、Nginx/Redis/MySQL/systemd 日志片段。
- 配置截图：Nginx 配置、systemd unit、crontab、防火墙规则等。
- 告警截图：Grafana、Prometheus、Zabbix、云监控、PagerDuty 类告警内容。
- 工单截图：标题、影响范围、错误描述、处理记录。

第一阶段不支持或弱支持：

- 超长滚动截图完整解析。
- 视频、GIF、屏幕录制。
- 大量图片批量分析。
- 需要精确坐标点击的 UI 自动化。

#### 5.1.2 图片上传入口

在现有聊天输入区增加附件按钮：

- 支持选择图片文件。
- 支持粘贴剪贴板图片。
- 支持拖拽上传到聊天区域。

上传后展示：

- 图片缩略图。
- 文件名、大小、格式。
- 删除按钮。
- “仅识别图片”和“识别并提问”两种行为：
  - 仅识别图片：只返回结构化识别结果，不进入工具执行。
  - 识别并提问：识别结果与用户文本一起进入 Agent。

#### 5.1.3 图片识别输出

图片识别服务需要输出结构化 JSON：

```json
{
  "input_type": "image",
  "image_category": "terminal_status | log | config | alert | ticket | unknown",
  "summary": "图片主要内容摘要",
  "extracted_text": "OCR 提取文本",
  "entities": {
    "services": ["nginx"],
    "ports": [80, 443],
    "paths": ["/etc/nginx/nginx.conf"],
    "commands": ["systemctl status nginx"],
    "error_keywords": ["permission denied", "failed"],
    "timestamps": ["2026-05-21 03:12:10"]
  },
  "diagnosis_hints": [
    "疑似服务启动失败",
    "建议检查服务状态和最近日志"
  ],
  "recommended_tools": [
    {
      "tool": "get_service_status",
      "args": { "service": "nginx" },
      "reason": "截图中出现 nginx 服务状态"
    }
  ],
  "confidence": "high | medium | low",
  "warnings": [
    "截图分辨率较低，部分文字可能识别不准"
  ]
}
```

#### 5.1.4 图片进入 Agent 的方式

图片识别结果不直接执行工具，而是追加为一段系统上下文：

```text
用户上传了一张运维截图，系统识别结果如下：
- 图片类型：终端服务状态截图
- 识别到服务：nginx
- 识别到错误：permission denied, failed
- 建议检查：get_service_status(nginx), get_service_logs(nginx)

注意：以上是图片识别结果，可能存在误识别。涉及系统状态时必须通过真实 MCP 工具确认。
```

Agent 回复必须遵守：

- 可以说“截图中识别到……”
- 不可以说“系统当前确认为……”，除非真实工具已执行。
- 涉及写操作时，必须走影响评估和审批。

### 5.2 语音输入

#### 5.2.1 交互入口

在聊天输入区增加语音按钮：

- 点击开始录音，再次点击结束。
- 暂不做移动端按住说话专项交互。
- 录音结束后先转文字，文字自动填入输入框。
- 用户可以编辑识别文本后再发送。
- 配置项允许开启“识别后自动发送”，默认关闭。

#### 5.2.2 语音识别能力

语音输入需要支持：

- 中文普通话。
- 中文运维口语。
- 中英混合术语：
  - nginx
  - systemctl
  - journalctl
  - MySQL
  - Redis
  - Docker
  - Kubernetes
  - Prometheus
  - Grafana
- 数字、端口、路径、服务名识别。

#### 5.2.3 运维术语纠错

语音识别结果进入 Agent 前，需要经过运维词表纠错。

示例：

| 识别文本 | 纠错后 |
| --- | --- |
| 恩金叉 | nginx |
| 系统 CTL | systemctl |
| 八零端口 | 80 端口 |
| var log messages | /var/log/messages |
| etc 恩金叉 | /etc/nginx |
| 查看瑞迪斯状态 | 查看 redis 状态 |

纠错输出结构：

```json
{
  "raw_transcript": "帮我看一下恩金叉为什么挂了",
  "normalized_transcript": "帮我看一下 nginx 为什么挂了",
  "corrections": [
    {
      "from": "恩金叉",
      "to": "nginx",
      "reason": "运维词表匹配"
    }
  ],
  "confidence": "medium"
}
```

#### 5.2.4 写操作复述确认

如果语音内容涉及写操作或破坏性操作，系统必须先生成可见确认文本：

```text
语音识别结果：帮我重启 nginx 服务
系统理解为：重启 nginx 服务
该操作可能导致短暂服务中断。是否继续进入审批流程？
```

用户确认后，才允许进入现有审批/执行链路。

这一步不能替代原有审批，而是位于审批前，用来防止语音识别错误导致误操作。

#### 5.2.5 语音输入推理链路

推理链路新增事件：

- 阶段：语音识别
- 内容：
  - 原始识别文本
  - 纠错后文本
  - 纠错项
  - 置信度
  - 是否触发写操作复述确认

示例：

```text
语音识别完成
原始文本：帮我看一下恩金叉为什么挂了
纠错后：帮我看一下 nginx 为什么挂了
来源：阿里云语音识别 + 运维词表纠错
执行状态：已识别，未执行系统操作
```

## 6. 阿里云服务选型

### 6.1 图片识别建议

建议优先使用阿里云百炼 Model Studio 的视觉模型能力：

- 通用图片理解：Qwen-VL / Qwen3-VL 视觉理解模型。
- 运维截图 OCR 与结构化抽取：qwen-vl-ocr。

选择理由：

- qwen-vl-ocr 面向文档、表格、手写内容等文字提取场景优化，适合终端截图、配置截图、日志截图和告警截图。
- 支持图像输入和结构化信息抽取，适合输出 OpsGuard 需要的 JSON。
- 百炼模型接口可以作为后端服务封装，避免前端暴露 API Key。

使用约束：

- 图片识别存在幻觉风险，尤其是分辨率低、文字过小、遮挡、倾斜时。
- qwen-vl-ocr 对 system message、多轮对话等能力存在限制，提示词应通过 user message 传入。
- 图片大小、格式和 token 成本需要在上传前做限制。

### 6.2 语音识别建议

语音侧有两条可选路线：

#### 路线 A：阿里云百炼 Qwen-ASR-Realtime

适合第一阶段语音输入：

- WebSocket 实时音频流输入。
- 文本流式输出。
- 支持 VAD 自动断句和 Manual 模式。
- 可选择 qwen3-asr-flash-realtime、qwen3.5-omni 相关实时模型。

建议用于：

- 用户点击录音后，实时或近实时显示识别文本。
- 后续扩展为实时语音助手。

#### 路线 B：阿里云智能语音交互 ASR

适合传统语音识别能力：

- 一句话识别。
- 实时语音识别。
- 录音文件识别。
- 服务端、WebSocket、RESTful 等多种接入方式。

建议用于：

- 如果项目希望稳定使用传统 ASR 产品线。
- 如果需要更明确的热词、方言、录音文件识别产品能力。

### 6.3 本 PRD 推荐

第一阶段推荐：

- 图片：阿里云百炼 `qwen-vl-ocr` + 通用视觉理解模型。
- 语音：优先调研并接入百炼 `qwen3-asr-flash-realtime` 或 `fun-asr-realtime`。
- 备选：阿里云智能语音交互的一句话识别/实时语音识别。

封装原则：

- 后端定义 `MultimodalProvider` 抽象。
- 阿里云实现为 `AliyunMultimodalProvider`。
- 前端不直接调用阿里云。
- API Key 只存放在后端环境变量。

参考资料：

- 阿里云 qwen-vl-ocr API 参考：https://help.aliyun.com/zh/model-studio/qwen-vl-ocr-api-reference
- 阿里云百炼语音识别模型文档：https://help.aliyun.com/zh/model-studio/asr-model/
- 阿里云 Qwen-ASR-Realtime 文档：https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-api/
- 阿里云 Qwen-ASR-Realtime WebSocket 流程：https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-interaction-process

## 7. 系统设计

### 7.1 前端模块

新增或改造：

- ChatPanel：
  - 图片上传按钮。
  - 图片粘贴/拖拽上传。
  - 语音录音按钮。
  - 识别结果编辑区。
- MarkdownRenderer：
  - 多模态识别结果摘要展示。
- TracePanel：
  - 新增图片识别、语音识别证据类型。
  - 展示识别来源、置信度、纠错记录。

前端状态：

```ts
interface PendingAttachment {
  id: string
  type: 'image' | 'audio'
  filename: string
  size: number
  previewUrl?: string
  status: 'pending' | 'uploading' | 'recognized' | 'failed'
  recognition?: MultimodalRecognitionResult
}
```

### 7.2 后端 API

新增 API：

```text
POST /api/multimodal/images/analyze
POST /api/multimodal/audio/transcribe
POST /api/multimodal/audio/normalize
```

可选 API：

```text
POST /api/multimodal/attachments
GET  /api/multimodal/attachments/{id}
```

后端职责：

- 文件格式校验。
- 文件大小限制。
- 调用阿里云服务。
- 结构化识别结果。
- 敏感信息脱敏。
- 写入审计日志。
- 将识别结果作为上下文传给 Agent。

### 7.3 Agent 集成

Agent 输入结构扩展：

```json
{
  "user_message": "帮我看一下这个报错",
  "multimodal_context": [
    {
      "type": "image",
      "source_id": "attachment_xxx",
      "summary": "...",
      "entities": {},
      "recommended_tools": [],
      "confidence": "medium"
    }
  ]
}
```

Prompt 约束：

- 多模态识别结果是“用户提供证据”，不是系统真实状态。
- 必须用真实工具验证状态。
- 不得因为图片或语音内容直接声称已执行操作。
- 对低置信度识别结果应询问用户或选择只读检查。

### 7.4 审计与知识库

多模态结果需要进入审计日志：

- attachment_id
- 输入类型
- 原始文件名
- 文件 hash
- 识别服务
- 模型名称
- 识别结果摘要
- 置信度
- 是否被用于 Agent 推理

知识库沉淀规则：

- 图片/语音本身不自动沉淀为经验。
- 只有当一次故障处理完成，并且最终结论有真实工具证据时，才允许把多模态识别摘要作为辅助上下文沉淀。
- 知识库条目必须标注来源：`image_recognition`、`voice_transcription`、`real_tool_execution`。

## 8. 安全与隐私

### 8.1 文件安全

- 限制上传类型：jpg、jpeg、png、webp；音频 wav、mp3、m4a、webm。
- 限制图片大小：默认 10MB 以内。
- 限制音频时长：第一阶段建议 60 秒以内。
- 文件存储使用随机 ID，不使用原始文件名作为路径。
- 禁止执行图片或音频中识别出的命令。

### 8.2 凭证与敏感信息

图片和语音可能包含：

- AccessKey
- Token
- 密码
- 内网 IP
- 域名
- 用户名
- 工单信息

要求：

- 识别结果进入前端展示前，执行基础脱敏。
- 发送给模型前尽量不裁剪运维关键信息，但需要在审计存储中脱敏高危凭证。
- 用户可手动删除附件。
- API Key 只保存在后端环境变量。

### 8.3 写操作安全

- 图片中的命令不能自动执行。
- 语音中的写操作必须先复述确认。
- 确认后仍需走现有审批流程。
- 推理链路必须明确显示：语音/图片识别阶段未执行系统操作。

## 9. 非功能需求

### 9.1 性能

- 图片识别 P95：10 秒以内。
- 语音转写 P95：录音结束后 5 秒以内返回第一版文本。
- 语音实时模式：逐步返回中间文本，不阻塞 UI。

### 9.2 可用性

- 阿里云服务不可用时，返回明确错误：
  - “图片识别服务暂不可用，请改用文字描述或稍后重试。”
  - “语音识别失败，请检查麦克风权限或改用文字输入。”
- 多模态失败不影响文本对话能力。

### 9.3 成本控制

- 默认限制单次图片数量：3 张。
- 默认限制单次语音时长：60 秒。
- 对图片做前端压缩和后端二次校验。
- 后端记录 token/调用次数/耗时，为后续成本报表预留字段。

## 10. 分期计划

### Phase 1：基础图片识别与语音转文字

目标：可用、可信、接入主链路。

功能：

- 图片上传。
- 调用阿里云 qwen-vl-ocr 识别截图文字。
- 输出结构化识别结果。
- 语音录音。
- 调用阿里云 ASR 转文字。
- 语音文字可编辑后发送。
- 推理链路显示图片/语音识别证据。

验收：

- 上传 nginx status 截图，能识别 nginx、failed、关键错误行。
- 上传日志截图，能提取错误关键字和路径。
- 语音说“帮我看一下 nginx 为什么挂了”，输入框出现合理文本。
- 图片/语音识别结果不会被标记为真实系统执行结果。

### Phase 2：运维语义增强

目标：让多模态输入更懂运维。

功能：

- 运维词表纠错。
- 服务名、端口、路径、命令、错误码实体抽取。
- 图片识别结果推荐只读 MCP 工具。
- 低置信度提示用户确认。
- 写操作语音复述确认。

验收：

- “恩金叉”能纠错为 nginx。
- 截图里出现 `/etc/nginx/nginx.conf` 时能推荐读取配置或检查语法。
- 语音说“重启 nginx”时不会直接执行，而是先复述确认。

### Phase 3：多模态知识与报告

目标：让多模态成为事件资产。

功能：

- 多模态识别摘要进入事件时间线。
- 运维报告中展示多模态证据。
- 成功闭环后，把多模态摘要作为辅助上下文沉淀到知识库。
- 支持从历史对话回放图片/语音识别结果。

验收：

- 运维报告能显示“用户上传截图识别到的错误”和“真实工具验证结果”。
- 历史对话切回后，图片/语音识别推理链路仍可见。
- 知识库不会只因为图片/语音识别成功就沉淀经验。

## 11. 验收用例

### 11.1 图片识别

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 终端状态截图 | 上传 `systemctl status nginx` 截图 | 识别服务 nginx、状态、错误关键词，并推荐服务状态/日志检查 |
| 日志截图 | 上传 Nginx error log 截图 | 提取错误行、路径、时间，推荐读取日志或配置 |
| 配置截图 | 上传 nginx.conf 截图 | 提取配置片段，提示可能需要真实读取文件确认 |
| 告警截图 | 上传 Grafana 告警截图 | 提取指标名、服务、时间范围、阈值和建议检查 |
| 模糊截图 | 上传低清图片 | 返回低置信度和“可能识别不准”的提示，不自动执行 |

### 11.2 语音输入

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 普通查询 | 说“查看 nginx 当前状态” | 转为文本后进入只读查询 |
| 术语纠错 | 说“恩金叉为什么挂了” | 纠错为 nginx，并展示纠错记录 |
| 写操作 | 说“帮我重启 nginx” | 先复述确认，再走审批，不直接执行 |
| 路径识别 | 说“查看 var log messages” | 纠错为 `/var/log/messages` 或提示用户确认 |
| 识别失败 | 麦克风无权限或无声音 | 明确错误提示，不影响文字输入 |

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| OCR 幻觉 | 错误诊断 | 明确标注识别置信度，必须真实工具验证 |
| 语音识别错误 | 误解用户意图 | 识别后可编辑，写操作先复述确认 |
| 云服务不可用 | 多模态不可用 | 文本链路降级可用 |
| 成本不可控 | 调用费用增加 | 限制文件大小、时长、数量，记录调用成本 |
| 敏感信息泄露 | 安全风险 | 后端脱敏、附件删除、API Key 后端保存 |
| 模型输出 JSON 不稳定 | Agent 上下文污染 | 后端做 schema 校验，不合格结果降级为文本摘要 |

## 13. 开放问题

- 阿里云模型地域选择：北京、新加坡或其他地域，需结合用户部署位置和数据合规决定。
- 是否需要热词自定义：如果 ASR 模型支持热词，应沉淀 OpsGuard 运维词表。
- 图片是否需要长期保存：第一阶段建议默认保存识别摘要，原图可配置是否保留。
- 语音原始音频是否保存：第一阶段建议默认不长期保存原始音频，只保存转写文本和审计摘要。
- 多模态识别结果是否计入知识库检索：建议只作为辅助字段，不作为主要匹配字段。

## 14. 成功指标

- 80% 以上常见终端截图能提取出服务名、错误关键词或路径。
- 语音输入后，用户手动修改率低于 30%。
- 涉及写操作的语音请求，100% 触发复述确认。
- 多模态识别失败时，文本对话能力不受影响。
- 用户能在推理链路中清楚区分：图片/语音识别、模型推断、真实工具执行。
