# OpsGuard 安全态势中心 PRD

## 1. 文档信息

- 文档状态：Draft
- 创建日期：2026-06-03
- 面向版本：OpsGuard 安全运营能力第一阶段
- 目标用户：运维人员、SRE、安全运维、平台工程师、值班人员、项目评委
- 产品定位：面向运维 Agent 的主机安全态势、威胁监控、证据化调查和审批式处置中心
- 本 PRD 聚焦：新增独立“安全态势”页面、安全数据大屏、主机安全扫描、攻击来源识别、入侵迹象分析、Agent 安全调查闭环
- 本 PRD 不替代：现有“安全演示/靶场”页面

## 2. 背景

OpsGuard 当前已经具备文本对话、真实 MCP 工具执行、审批、安全防护、推理链路、健康巡检、拓扑、知识库、运维报告和安全演示能力。

现有“安全演示”页面主要用于验证 OpsGuard Agent 自身的三层安全模型，包括 prompt injection、危险命令和高风险意图拦截。它解决的是“Agent 会不会被诱导执行危险行为”的问题。

但真实运维场景还存在另一类更直接的安全需求：

- 服务器是否正在遭遇 SSH 爆破、Web 扫描或异常连接。
- 是否存在恶意 IP、高频失败登录、可疑外连。
- 是否被植入可疑 cron、systemd 服务、后门用户或启动项。
- 是否存在木马脚本、可疑临时目录可执行文件、异常进程。
- 防火墙、SSH、账号权限、关键文件权限是否符合安全基线。
- 运维人员是否能从安全告警快速进入证据化调查和审批式处置。

因此，OpsGuard 需要新增一个独立的“安全态势”页面，把运维安全从单次对话能力升级为可视化、可监控、可解释、可处置的产品能力。

## 3. 页面定位

### 3.1 页面关系

| 页面 | 定位 | 保护对象 | 典型问题 |
| --- | --- | --- | --- |
| 安全演示/靶场 | 测试 Agent 三层安全防护 | Agent 自身 | Prompt injection 能否拦住、危险命令是否拒绝 |
| 安全态势中心 | 监控主机和服务安全风险 | 主机、账号、网络、服务、文件、配置 | 是否被攻击、是否有入侵迹象、该先处置什么 |

备选名称：

- 安全中心
- 安全运营
- 威胁监控

## 4. 产品目标

### 4.1 业务目标

1. 增强 OpsGuard 的安全运维竞争力，不只会“修故障”，也能“看风险、查攻击、给证据、辅助处置”。
2. 为项目演示提供直观的数据大屏，提升产品观感和完整度。
3. 将常见主机安全检查沉淀为可复用的只读扫描能力。
4. 让安全风险项可以一键进入 Agent 调查，形成证据链和建议操作。
5. 为后续接入 Elkeid、ClamAV、YARA、威胁情报、SIEM 告警预留扩展点。

### 4.2 用户体验目标

- 用户进入页面即可看到当前安全评分、严重风险、攻击来源和推荐处置。
- 用户无需熟悉安全命令，也能理解“风险是什么、证据是什么、下一步做什么”。
- 每个风险项都能展开查看证据来源、检测时间、命中规则和影响说明。
- 每个风险项都能一键发起 Agent 调查。
- 任何封禁 IP、锁定用户、删除文件、修改 SSH 配置、改防火墙等动作都必须走现有审批机制。

### 4.3 技术目标

- 第一阶段优先复用现有 MCP 工具和本机系统数据，不强依赖外部安全平台。
- 所有检测结果必须区分真实工具证据、日志解析、规则推断和 Agent 推理。
- 安全扫描默认只读，不能在页面加载时执行写操作。
- 支持定时刷新和手动刷新，但要避免频繁执行高成本命令。
- 风险项、扫描结果和 Agent 调查结果可以进入现有 incident/trace/report 能力。

## 5. 非目标

第一阶段不做：

- 不做完整 EDR/CWPP 平台。
- 不直接替代 Elkeid、Falco、Wazuh、ClamAV、商业态势感知或 SIEM。
- 不自动封禁 IP、自动删除文件、自动锁用户。
- 不承诺病毒查杀能力，只做可疑迹象检测和可选扫描集成。
- 不做多租户安全运营中心。
- 不做云厂商全资产安全管理。
- 不做复杂攻击图谱和 MITRE ATT&CK 全量映射。

## 6. 竞品与参考

### 6.1 Elkeid

Elkeid 是字节跳动开源的云原生主机安全平台，覆盖 CWPP、HIDS、RASP、K8s Audit Log、资产采集、规则引擎 Elkeid HUB、恶意文件/风险发现等方向。

对 OpsGuard 的启发：

- 安全能力应覆盖主机、容器、K8s、应用运行时等多层面。
- 采集 Agent 和规则引擎是长期方向，但第一阶段不必自建完整体系。
- 安全告警应落到“证据、影响、处置建议、闭环状态”。
- 后续可以把 Elkeid 作为外部安全数据源接入 OpsGuard，由 OpsGuard Agent 做解释、关联和处置编排。

### 6.2 Wazuh / OSSEC 类 HIDS

参考点：

- 文件完整性监控。
- Rootkit/异常进程检查。
- 登录审计和规则告警。
- 安全配置评估。

### 6.3 云厂商安全中心

参考点：

- 安全评分。
- 风险分类和优先级。
- 漏洞、基线、入侵、暴露面、告警趋势。
- 一键处置和工单闭环。

## 7. 用户画像与场景

### 7.1 值班运维

场景：

- 夜间发现服务器负载异常，想确认是否被攻击。
- 收到 SSH 登录失败告警，想查看攻击 IP 和风险程度。
- 发现服务异常外连，想快速判断是否被植入。

需求：

- 快速看当前风险。
- 一键让 Agent 调查。
- 能看到证据，而不是只看模型猜测。

### 7.2 SRE / 平台工程师

场景：

- 需要定期检查主机安全基线。
- 希望把暴露端口、异常账号、异常服务纳入日常巡检。
- 希望安全风险能和运维报告、事件报告打通。

需求：

- 周期性扫描。
- 风险趋势。
- 可导出报告。

### 7.3 安全运维

场景：

- 发现可疑 IP 攻击。
- 需要定位攻击入口、登录痕迹和持久化方式。
- 希望封禁、锁定、隔离等操作可审计。

需求：

- 事件时间线。
- 攻击来源。
- 处置动作审批和审计。

### 7.4 项目评委 / 新用户

场景：

- 进入系统后希望直观看到安全运营能力。
- 希望看到数据大屏、风险评分、威胁列表和 Agent 调查能力。

需求：

- 页面有视觉冲击力。
- 数据解释清楚。
- 功能闭环完整。

## 8. 核心功能范围

## 8.1 安全总览

展示当前主机安全态势：

- 安全评分：0-100。
- 风险等级：健康、关注、警告、危险。
- 严重风险数量。
- 今日攻击来源 IP 数。
- 当前暴露端口数。
- 可疑登录事件数。
- 可疑持久化项数量。
- 最近扫描时间。

安全评分建议由规则扣分组成：

| 风险项 | 示例扣分 |
| --- | --- |
| SSH 高频失败登录 | -10 |
| 存在成功登录紧跟失败爆破来源 | -20 |
| 防火墙未启用 | -15 |
| 暴露危险端口 | -10 |
| 存在 UID 0 异常用户 | -30 |
| 存在可疑 cron 或 systemd 持久化 | -20 |
| `/tmp` 存在可执行脚本/二进制 | -10 |
| SSH 允许 root 登录 | -10 |
| 关键文件权限异常 | -20 |

## 8.2 攻击来源监控

目标：覆盖“别人的 IP 攻击”等场景。

第一阶段检测：

- SSH 登录失败来源 IP Top N。
- SSH 登录成功来源 IP。
- 同一 IP 高频失败登录。
- Nginx/HTTP access log 高频访问 IP。
- 4xx/5xx 异常访问来源。
- 可疑扫描路径：`/wp-admin`、`/.env`、`/phpmyadmin`、`/cgi-bin` 等。
- 当前网络连接中外部 IP Top N。

页面展示：

- Top 攻击 IP 表。
- 攻击类型标签：SSH 爆破、Web 扫描、异常连接、失败登录。
- 次数、首次发现、最近发现、涉及服务。
- 风险等级。
- 建议动作：调查、封禁 IP、加入观察列表。

处置要求：

- 封禁 IP 必须走审批。
- 第一阶段可先提供“生成封禁建议”，不直接执行。

## 8.3 入侵迹象检测

检测主机是否存在被入侵后的常见痕迹。

第一阶段检查项：

- 最近登录记录。
- 登录失败与成功登录关联。
- 新增用户。
- UID 0 非 root 用户。
- sudo 组或 wheel 组异常成员。
- 最近 sudo 命令记录。
- 可疑 cron 任务。
- 可疑 systemd service。
- authorized_keys 最近变化。
- `/tmp`、`/var/tmp`、`/dev/shm` 下可执行文件。
- 异常长时间运行进程。
- 进程命令行包含 `curl | sh`、`wget | bash`、反弹 shell 特征。

页面展示：

- 风险列表。
- 风险类型。
- 证据摘要。
- 命中规则。
- 推荐下一步检查。

## 8.4 恶意文件和木马可疑项

第一阶段定位为“可疑项发现”，不是完整杀毒。

检查项：

- 临时目录可执行文件。
- 隐藏文件和隐藏目录。
- 最近 24/72 小时新增可执行文件。
- 文件名伪装：`kworker`、`sshd`、`systemd`、`init` 等出现在异常路径。
- 脚本中包含下载执行、挖矿、反弹 shell、可疑域名/IP。
- 大量异常 CPU 占用进程对应的可执行路径。

后续增强：

- ClamAV 扫描结果接入。
- YARA 规则扫描。
- Elkeid scanner 结果接入。
- 文件哈希威胁情报查询。

## 8.5 暴露面检查

检查当前主机对外暴露情况。

第一阶段检查项：

- 当前监听端口。
- 监听地址是否为 `0.0.0.0`。
- 防火墙状态。
- 防火墙放行端口。
- 监听服务与防火墙放行是否一致。
- 危险服务暴露：SSH、Redis、MySQL、PostgreSQL、Docker API、Elasticsearch、MongoDB、Kubernetes API 等。

页面展示：

- 端口。
- 协议。
- 监听地址。
- 进程/服务。
- 防火墙状态。
- 风险等级。
- 推荐动作。

## 8.6 账号与权限安全

检查账号体系风险。

第一阶段检查项：

- root 登录风险。
- 人类用户列表。
- sudo/wheel 成员。
- UID 0 用户。
- 最近登录时间。
- 失败登录次数。
- shell 是否可登录。
- 用户 home 目录权限。

推荐动作：

- 调查用户。
- 锁定用户。
- 移出 sudo 组。
- 调整 SSH 策略。

所有修改类动作必须审批。

## 8.7 基线检查

第一阶段基线：

- SSH 是否允许 root 登录。
- SSH 是否允许密码登录。
- 防火墙是否启用。
- 关键文件权限：`/etc/passwd`、`/etc/shadow`、`/etc/sudoers`。
- 审计日志是否可读。
- 系统更新风险。
- Cron/systemd 是否存在可疑项。
- 包管理器是否有安全更新。

页面展示：

- 检查项。
- 状态：通过、警告、失败、未知。
- 证据。
- 修复建议。

## 8.8 安全事件时间线

把安全相关发现按时间串联。

事件类型：

- 登录失败。
- 登录成功。
- sudo 提权。
- 新增用户。
- 创建 cron。
- 创建 systemd 服务。
- 开放端口。
- 防火墙变更。
- 可疑文件创建。
- 可疑外连。

目标：

- 帮助用户发现攻击链。
- 为 Agent 生成调查上下文。
- 为报告输出提供素材。

## 8.9 Agent 安全调查

每个风险项支持“让 Agent 调查”。

交互：

1. 用户点击风险项上的“调查”。
2. 系统生成一条结构化用户问题，例如：
   `请调查安全风险：SSH 爆破来源 1.2.3.4，最近 1 小时失败 120 次，检查是否有成功登录和持久化迹象。`
3. 自动进入对话页或在右侧抽屉展示 Agent 调查。
4. Agent 必须调用本轮只读工具获取证据。
5. 最终输出结论、证据、影响、建议操作和未确认项。

约束：

- Agent 不能仅凭页面风险摘要下结论。
- 所有当前事实必须来自本轮工具或已保存扫描证据。
- 建议动作可包含写操作，但执行必须进入审批。

## 8.10 安全报告

支持生成安全态势报告：

- 当前安全评分。
- 风险摘要。
- 攻击来源 Top N。
- 暴露面。
- 入侵迹象。
- 基线失败项。
- 已处理/未处理风险。
- Agent 调查结论。
- 建议整改清单。

第一阶段可先支持页面内 Markdown 报告，后续接入 PDF 导出。

## 12. Agent 与审批设计

### 12.1 只读调查

安全态势页面的扫描和调查默认只读。

Agent 可以调用：

- 日志读取。
- 进程查看。
- 连接查看。
- 文件信息查看。
- 用户信息查看。
- 防火墙状态查看。

### 12.2 高风险处置

以下动作必须审批：

- 封禁 IP 或关闭端口。
- 修改防火墙规则。
- 锁定/删除用户。
- 删除或隔离可疑文件。
- 修改 SSH 配置。
- 停止/禁用服务。
- 修改 cron/systemd。
- 安装杀毒或安全软件包。

审批弹窗必须展示：

- 风险项来源。
- 操作目标。
- 影响范围。
- 预览结果。
- 回滚能力。
- 证据链接。

## 14. 验收标准

### 14.1 页面验收

- 安全演示页面仍可独立访问。
- 新增安全态势页面可独立访问。
- 页面加载后不会执行任何写操作。
- 用户可以手动触发扫描。
- 扫描中、成功、失败、部分失败状态清晰。
- 风险列表可按严重等级和分类过滤。
- 风险项可展开查看证据。
- 风险项可触发 Agent 调查。

### 14.2 检测验收

- 能识别 SSH 失败登录来源 IP。
- 能列出当前监听端口和进程。
- 能识别防火墙状态。
- 能列出人类用户和 root。
- 能发现 UID 0 异常用户。
- 能检查 SSH root 登录配置。
- 能展示至少 5 类基线检查。
- 能生成安全评分和扣分原因。

### 14.3 Agent 验收

- Agent 调查必须包含本轮证据。
- Agent 不能把历史扫描误称为当前事实，除非重新扫描或注明时间。
- Agent 建议写操作时必须走审批。
- 处置执行后必须验证。
- 推理链路中能看到安全风险来源和工具证据。

### 14.4 数据大屏验收

- 顶部关键指标在 1 秒内显示最近一次扫描结果。
- 手动扫描完成后指标刷新。
- Top 攻击 IP 和暴露端口表可展示空状态。
- 空状态不能假造攻击数据。
- 演示环境可通过固定 fixture 或 mock 数据展示大屏效果，但必须清楚标记为演示数据。

## 15. 风险与约束

### 15.1 误报

安全检测容易误报。例如高频访问不一定是攻击，临时目录可执行文件也可能是合法脚本。

应对：

- 风险项展示置信度。
- 支持标记为误报。
- Agent 回复必须说明证据和不确定性。

### 15.2 权限不足

部分日志和文件需要 root 权限。

应对：

- 工具失败时展示权限不足。
- 不伪造结果。
- 提供最小权限建议。

### 15.3 性能开销

扫描文件系统和日志可能耗时。

应对：

- P0 限制扫描路径和时间窗口。
- 大文件扫描必须设置 limit。
- 页面自动刷新使用最近结果，不频繁全量扫描。

### 15.4 安全处置风险

封禁 IP、锁用户、删文件可能影响业务。

应对：

- 默认只给建议。
- 执行必须审批。
- 审批前展示影响和回滚能力。
- 执行后验证。

## 16. 成功指标

- 用户能在 10 秒内理解当前安全风险。
- P0 至少覆盖 5 类安全风险。
- 每个高危风险都有证据和下一步建议。
- Agent 调查中当前事实 100% 来自工具或扫描证据。
- 所有写操作审批覆盖率 100%。
- 演示环境中安全态势页面能显著提升系统完整度和竞争力。
