## 3. 核心功能测试细节展示

### A. 智能问答及右侧推理链路 (C-01 至 C-04)
在主问答界面，用户发送诊断请求后，进度面板与推理链路均实时反映底层 MCP 工具的真实调用（非模拟文案）。
推理链路中包含：安全三层防御校验 (Classifier)、知识库检索 (Knowledge Search) 以及最近系统变更捕获 (Recent Changes)，每一个节点均有实际的 `executed` 状态和命令执行返回结果作为佐证。

### B. 安全三层防御与攻击拦截演示 (G-01 至 G-03)
安全演示页展示了主动阻断功能。一旦检测到高危系统命令（如 `rm -rf /`）或典型的 LLM 注入攻击指令，安全引擎将直接拦截并呈报具体拦截防御层及命中规则。

### C. 运维 Runbook 静态校验机制 (RB-01, RB-07)
系统在保存 Runbook 时会记录全部动作参数及风险标签。执行或预演前点击 "校验"，会静态扫描系统目录与配置，智能发现预检失败项（如路径缺失等），避免直接运行导致的级联故障。

### D. Incident 自动化 Handoff 与 Postmortem 草稿 (I-05, I-06)
在运维日报页，系统允许评委/运维人员一键生成交接与复盘文档。报告抽取自 Incident 时间线中记录的真实动作、确认的事实以及系统观测，保证了数据的百分之百真实性。

## 4. 总结与改进建议

### 产品亮点
1. **全链路真实调用**：不论是系统状态、日志、还是文件修改，均能通过底层 Python 系统库与 Linux 命令真实交互，实现了真正的运维闭环。
2. **完备的安全隔离**：写操作审批弹窗阻断效果明显，对危险命令和输入注入的防范级别高（支持 Heuristic 正则匹配、分类器模型、安全边界和 LLM 语义审查多重护栏）。
3. **告警分诊迅速**：外部 Prometheus/Alertmanager webhook 告警触发后，在没有人类干预下能够自动执行一整套只读的排查指令，并为人工介入留存完整的 Incident 记录。

### 可优化点 (P2/P3)
1. **拓扑图 Hover 效果**：在 Kylin V11 等部分浏览器环境下，拓扑节点 hover 时可能缺乏显式的标准 HTML Tooltip。建议对拓扑 Canvas 组件的鼠标悬停交互进行微调，增强对节点实时指标的浮窗展示。
2. **Runbook 手动修改**：目前 Runbook 步骤大多依赖历史成功诊断自动生成，可以在后续迭代中开放可视化的手工步骤编辑，让用户能够直接在 UI 上微调参数。
